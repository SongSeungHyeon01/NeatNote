# ✍️ NeatNote

> 악필도 깔끔하게 — 필기 보정 · 강의 녹음 · 온디바이스 AI 필기 메모앱

손으로 쓴 필기를 알아보기 쉬운 글씨로 보정해 주고, 말이 빠른 강의도 녹음과 AI 필기로 놓치지 않게 돕는 메모앱입니다. 안드로이드와 iOS에서 모두 동작하고, 서버 없이 기기 안에서 처리하는 것을 목표로 합니다.

## 🛠 기술 스택

- **앱**: Flutter (Android · iOS)
- **필기 인식**: 미정 (후보: Google ML Kit Digital Ink Recognition — 기기 안에서 동작, 한국어 지원)
- **녹음 → 텍스트**: 미정 (후보: Whisper 계열 온디바이스 모델)
- **AI 필기**: 미정
- 서버 없이 **온디바이스** 처리가 원칙
- 오픈소스는 **상업적 이용 가능 라이선스(MIT/Apache 2.0/BSD)** 만 사용

> AI API를 쓸 경우 API 키를 앱에 넣으면 앱 파일에서 키를 꺼낼 수 있습니다. 사용자 본인 키 입력 방식과 완전 온디바이스 방식 중 하나로 정할 예정입니다.

## 🤝 협업 규칙

### 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 안정 버전 — **직접 푸시 금지**, PR로만 합침 |
| `feature/<기능>` | 기능 개발 (예: `feature/handwriting`, `feature/recording`) |
| `fix/<내용>` | 버그 수정 |
| `docs/<내용>` | 문서 수정 |

### 작업 순서
1. 작업 전 `main`을 최신으로 받는다 (`git pull`)
2. `main`에서 자기 작업 브랜치를 만든다
3. 작업이 일단락되면 **`main`으로 Pull Request(PR)** 를 올린다
4. 상대방이 확인한 뒤 합친다

### 커밋 메시지
`종류(범위): 설명` 형식으로, 설명은 한국어로 씁니다.

```
feat(recording): 강의 녹음 시작·정지 버튼 추가
fix(handwriting): 필기 중 획이 끊기던 문제 수정
docs: README 역할 표 갱신
```

### ⚠️ 꼭 지킬 규칙
- **`main`에 직접 푸시하지 말 것** — 반드시 브랜치에 올리고 PR로 합치기
- **API 키 · 비밀값은 절대 올리지 말 것** — `.env`에만 넣기 (`.gitignore`가 걸러 줌)
- **무거운 파일은 올리지 말 것** — AI 모델 파일, 녹음 파일, 빌드 결과물은 `.gitignore`가 자동으로 거름
- **공용 파일(`README.md`, `.gitignore`, `pubspec.yaml`)은 바꾸기 전에 상대에게 먼저 말하기** — 동시에 고치면 충돌이 납니다
