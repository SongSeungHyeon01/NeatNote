# ✍️ NeatNote

> **악필도 깔끔하게** | 필기 보정 · 강의 녹음 · 온디바이스 AI 필기 메모앱 | Android · iOS

## 📌 프로젝트 소개

강의 시간에 교수님 말이 빠르면 받아 적기 바빠서 글씨가 점점 무너집니다. 수업이 끝나고 노트를 다시 펴면 내가 쓴 글씨를 내가 못 읽고, 놓친 설명은 어디서도 다시 들을 수 없습니다.

NeatNote는 펜으로 쓴 필기를 인식해 알아보기 쉬운 글씨로 바꿔 주고, 보정된 글씨를 원하는 폰트로 바꿔 볼 수 있게 합니다. 필기하는 동안 강의를 녹음해 두면 녹음 원본을 바로 텍스트로 뽑아 주고, 그 내용을 바탕으로 AI가 필기를 정리합니다. 강의 녹음과 필기는 개인 자료이므로 서버로 보내지 않고 **기기 안에서 처리하는 것**을 원칙으로 합니다.

## 🏗️ 시스템 아키텍처 (계획)

```
   펜 · 손가락 입력              마이크
         │                        │
         ▼                        ▼
   필기 캔버스                 강의 녹음
         │                        │
         ▼                        ▼
   손글씨 인식 (기기 안)       음성 → 텍스트 (기기 안)
         │                        │
         ▼                        ▼
   글씨 보정 · 폰트 적용  ◄──  AI 필기 정리
         │
         ▼
   기기 내 저장소 (노트 · 녹음 · 텍스트)
```

**설계에서 지킬 세 가지**

1. **서버 없이 기기 안에서 동작합니다.** 강의 녹음과 필기는 개인 자료라 밖으로 보내지 않습니다. 인터넷이 없는 강의실에서도 쓸 수 있어야 합니다.
2. **API 키를 앱에 넣지 않습니다.** 외부 AI API를 쓰게 되더라도 앱 파일 안에 키를 넣으면 누구나 꺼낼 수 있습니다. 사용자 본인 키 입력 방식과 완전 온디바이스 방식 중 하나로 정합니다.
3. **상업적 이용이 자유로운 라이선스만 씁니다.** 오픈소스와 모델은 MIT · Apache 2.0 · BSD 등만 사용합니다.

| 분류 | 기술 |
|---|---|
| 앱 | Flutter (Android · iOS) |
| 필기 인식 | 미정 — 후보: Google ML Kit Digital Ink Recognition (기기 안에서 동작, 한국어 지원) |
| 음성 → 텍스트 | 미정 — 후보: Whisper 계열 온디바이스 모델 |
| AI 필기 | 미정 |

## ✨ 주요 기능 (계획)

### 필기
- 펜 · 손가락으로 필기하고, 손글씨를 인식해 알아보기 쉬운 글씨로 보정합니다.
- 보정된 글씨를 원하는 폰트로 바꿔 봅니다.

### 강의
- 필기하면서 강의를 녹음합니다.
- 녹음 원본을 바로 텍스트로 뽑습니다.
- 녹음 내용을 바탕으로 AI가 필기를 정리합니다.

## 🚀 로컬 실행 방법

Flutter stable(3.47 이상)과 Android Studio(Android SDK)가 필요합니다. iOS 빌드는 Mac과 Xcode가 있어야 합니다. 2026년 10월 Windows 11에서 확인한 순서입니다.

```bash
flutter doctor   # 빠진 준비물 확인
flutter pub get  # 의존성 받기
flutter run      # 연결된 기기 · 에뮬레이터에서 실행
flutter test     # 테스트
```

- Android는 `flutter doctor`에서 Android toolchain이 √여야 합니다. cmdline-tools가 없다고 나오면 Android Studio → SDK Manager → SDK Tools에서 설치하고, `flutter doctor --android-licenses`로 라이선스에 동의합니다.
- Windows에서 `'WHERE' is not recognized` 오류가 나면 시스템 Path에 `%SystemRoot%\system32`가 빠진 것입니다.
- API 키 등 비밀값은 `.env`에만 넣습니다. 이 파일은 git에 올라가지 않습니다.

### 폴더 구조
```
lib/
  main.dart              앱 시작점 (공용)
  features/
    handwriting/         필기 캔버스 · 글씨 보정
    fonts/               폰트 변경
    recording/           강의 녹음 · 녹음 → 텍스트
    ai_note/             AI 필기
test/                    테스트
android/ · ios/          플랫폼별 설정
docs/                    작업 기록, 오류 보고서
UI/                      화면 캡처
```

기능마다 `lib/features/` 아래 정해진 폴더에서 작업합니다. 폴더 이름은 위 그대로 씁니다.

## 📋 브랜치 전략

```
main                      ← 안정 버전 (직접 푸시 금지, PR로만 합침)
├── feature/<기능>        ← 기능 개발 (예: feature/handwriting, feature/recording)
├── fix/<내용>            ← 버그 수정
└── docs/<내용>           ← 문서 수정
```

두 명이 한 저장소에서 동시에 작업하면서 서로의 코드를 덮어쓰지 않도록 다음 규칙을 정했습니다.

- 작업 전 `main`을 최신으로 받고(`git pull`), `main`에서 자기 작업 브랜치를 만듭니다.
- 각자 맡은 기능 폴더 안에서 작업하고, 작업이 일단락되면 `main`으로 PR을 올립니다. 상대방이 확인한 뒤 합칩니다.
- 공용 파일(`README.md`, `.gitignore`, `pubspec.yaml`, `lib/main.dart`)은 바꾸기 전에 상대에게 먼저 알립니다.
- API 키 · 비밀값, AI 모델 파일, 녹음 파일, 빌드 결과물은 올리지 않습니다. `.gitignore`가 걸러 주지만 실수하지 않도록 주의합니다.
- 커밋 메시지는 `종류(범위): 설명` 형식으로, 설명은 한국어로 씁니다.

```
feat(recording): 강의 녹음 시작·정지 버튼 추가
fix(handwriting): 필기 중 획이 끊기던 문제 수정
docs: README 역할 표 갱신
```
